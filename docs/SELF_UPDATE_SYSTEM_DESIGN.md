# Skills 自更新工作流系统设计

## 系统概述

这是一个智能的 Skills 推荐和自更新系统，具有以下特性：
- **实时推荐**：用户上线时自动调研并推荐 Skills
- **需求响应**：用户有新需求时自动调研并推荐合适的 Skills
- **定期自检**：系统定期检查并推荐更好的 Skills 选择

### 三大核心原则（不可违背）

1. **用户确认原则**
   - 所有更改都必须获得用户明确同意
   - 系统仅提供建议，不自动执行
   - 用户拒绝后系统不再次打扰

2. **版本控制原则**
   - 每次更改都有完整存档
   - 记录：更改原因、更改内容、更改前后对比
   - 可追溯的历史记录

3. **容错回退原则**
   - 保留至少 3 个历史版本
   - 用户可随时回退到上一版本
   - 出错时自动回退

## 功能模块设计

### 1. 用户上线检测模块

**触发条件**：`session.created` 事件

**工作流程**：
1. 读取当前配置的 Skills 列表
2. 分析用户最近项目类型和技术栈
3. 自动搜索相关 Skills 的最新描述
4. 生成推荐列表
5. 向用户展示推荐

**输出格式**：
```
👋 欢迎回来！

检测到你的项目类型：[项目类型]
当前 Skills：[列表]

🔍 发现 [N] 个可能感兴趣的 Skills：

1. **[skill-name]** - [描述]
   - 匹配度：高/中/低
   - 安装状态：已安装/未安装

是否需要安装或了解更多？
```

### 2. 需求响应模块

**触发条件**：用户提出当前 Skills 无法满足的需求

**工作流程**：
1. 解析用户需求
2. 提取关键技术和领域
3. 使用 websearch/Context7 大量调研可满足需求的 Skills
4. 生成二次确认列表，让用户选择侧重点
5. 根据侧重点排序推荐
6. 展示推荐并明确使用方法

**二次确认示例**：
```
我找到了 [N] 个可能满足需求的 Skills。

请告诉我你的侧重点：
1. 性能优先 - 关注执行速度和效率
2. 文档完善 - 优先选择文档详细的
3. 社区活跃 - 优先选择活跃维护的
4. 简单易用 - 优先选择学习曲线低的
5. 兼容性好 - 优先选择多工具兼容的

或者直接输入你的侧重点...
```

**推荐展示格式**：
```
根据你选择的 "[侧重点]"，推荐以下 Skills：

🥇 **[skill-name-1]** (推荐度: 95%)
- 描述：[描述]
- 安装：`npx skills add [url] --skill [name]`
- 侧重点匹配：✅ 性能 ✅ 文档

🥈 **[skill-name-2]** (推荐度: 85%)
- 描述：[描述]
- 安装：`npx skills add [url] --skill [name]`
- 侧重点匹配：✅ 性能

是否安装？回复 "安装 #1" 或 "安装 #2"
```

### 3. 定期自检模块

**触发条件**：
- 每周一次（可配置）
- 或用户手动触发 `/skill-check`

**工作流程**：
1. 扫描当前安装的所有 Skills
2. 对每个 Skill 类别，检查是否有更好的替代方案
3. 调研 Skills 之间的兼容性
4. 生成更新建议（如有）

**自检结果示例**：
```
📊 Skills 定期自检报告

| 当前 Skill | 评分 | 替代方案 | 建议 |
|-----------|------|---------|------|
| tdd-workflow | 9.0 | tdd-guide (9.5) | ⬆️ 建议更新 |

详细分析：
- tdd-guide 在测试覆盖率指导方面更详细
- 包含多框架支持 (Jest, Pytest, Vitest)
- 兼容性验证：✅ 与现有 Skills 无冲突

是否执行更新？
```

### 4. 版本控制模块

**版本文件格式**：
```json
{
  "version": "3",
  "timestamp": "2026-05-04T10:30:00Z",
  "reason": "添加新的调试技能",
  "changes": [
    {
      "action": "add",
      "skill": "syncause-debugger",
      "source": "Syncause/debug-skill",
      "before": null,
      "after": {
        "name": "syncause-debugger",
        "description": "运行时证据调试",
        "version": "1.0.0"
      }
    }
  ],
  "compatibility_check": {
    "tested": true,
    "conflicts": []
  },
  "created_by": "user"
}
```

**回退机制**：
- 用户说 "回退版本" → 恢复到上一版本
- 用户说 "回退到 v2" → 恢复到指定版本
- 每次回退都创建新存档记录原因

### 5. 用户确认机制

**确认请求格式**：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
⚠️ 需要你的确认

操作：[添加/替换/删除] [skill-name]
原因：[原因描述]
影响：
- 正面：[带来的好处]
- 风险：[可能的风险]

请回复：
- "确认" - 执行操作
- "拒绝" - 取消操作
- "详情" - 查看更多详情
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 实现细节

### 1. 核心配置文件

`config.json`:
```json
{
  "check_on_start": true,
  "periodic_check": {
    "enabled": true,
    "interval": "weekly",
    "day": "monday",
    "time": "09:00"
  },
  "auto_research": true,
  "max_history_versions": 5,
  "compatibility_check_before_change": true,
  "notification_channels": {
    "on_new_recommendation": true,
    "on_update_available": true,
    "on_periodic_check": false
  }
}
```

### 2. 安装命令

```bash
# 安装自更新系统
mkdir -p ~/.config/opencode/skills/skill-self-update
cp skill-self-update/SKILL.md ~/.config/opencode/skills/skill-self-update/
cp skill-self-update/config.json ~/.config/opencode/skills/skill-self-update/
```

## 使用示例

### 场景 1：用户上线

```
用户：打开 OpenCode

系统：→ 检测 session.created
      → 分析项目
      → 推荐 Skills
      → 等待用户响应
```

### 场景 2：用户有新需求

```
用户：帮我做一个数据分析的模块

系统：→ 解析需求：数据分析
      → 大量调研 Skills
      → 二次确认侧重点
      → 根据侧重点排序推荐
      → 等待用户确认
```

### 场景 3：定期自检

```
系统：→ 每周一自动触发
      → 扫描当前 Skills
      → 调研更好替代方案
      → 兼容性检查
      → 生成更新建议
      → 等待用户确认
```

### 场景 4：用户回退

```
用户：回退版本

系统：→ 读取上一版本记录
      → 显示回退内容
      → 等待确认
      → 执行回退
      → 存档记录
```
